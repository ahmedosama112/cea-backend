## التغييرات

- المصادقة تقرأ الحساب ودوره الحالي من قاعدة البيانات لكل طلب، بما فيها المصادقة الاختيارية للتسجيل. التوكن القديم لا يحتفظ بصلاحية أدمن مسحوبة، والحساب المحذوف لا يدخل.
- منع حذف ملفات `SubmissionRevision`، وإعادة فحص المراجع ضمن عملية الحذف نفسها.
- رفض اسم الصورة الأطول من 255 حرفًا قبل الكتابة، وتنظيف الملفات عند فشل إنشاء صفها في قاعدة البيانات (الصور وتسليمات Excel).
- تصحيح حارس مسار التخزين حتى لا يسمح بمجلد شقيق يبدأ بنفس الاسم. حدود لأعداد وأحجام حقول multipart.
- فحص بيانات Excel المضغوطة قبل تحميلها في ExcelJS: بحد أقصى 2048 عنصرًا و64 MiB إجماليًا بعد فك الضغط، والتحقق من الحجم الحقيقي باستخدام streams.
- لقطة قاعدة البيانات داخل transaction بعزل RepeatableRead؛ استمرار دعم إعداد Google بالاسم الأساسي أو اللاحقة `_1`.
- النسخة اليومية الجديدة إصدار 2: قاعدة البيانات وmanifest للملفات، وكل محتوى ملف ككائن منفصل باسم SHA-256 في مجلد **CEA Backup Files**. تُحفظ قاعدة البيانات والملفات المتاحة حتى لو توجد ملفات قديمة مفقودة، مع `missingFiles` و`fileBackupStatus: partial` وتحذير صريح. لا تُسجل النسخة الجزئية كنجاح كامل. أخطاء الصلاحية أو فشل الرفع لا تُعامل كملفات مفقودة، وإعادة المحاولة للفشل المؤقت تتم لكل ملف.
- Apps Script يتحقق من محتوى كائن الملف ويعيد استخدام نسخة مطابقة. ينشئ نسخة اليوم الجديدة ويتحقق من حجمها قبل حذف القديمة؛ يستخدم قفلًا لمنع تداخل استبدال النسخ. الاحتفاظ بآخر 30 نسخة قاعدة بيانات كما كان. كائنات الملفات لا تُحذف تلقائيًا، لأن نسخًا أقدم قد تحتاجها.
- حفظ وقت آخر نجاح في قاعدة البيانات عبر إعادة التشغيل. `/api/admin/backup-status` يعيد `lastSuccessAt` و`stale` بعد 36 ساعة بدون نجاح. هذه إشارة للمراقبة، وليست خدمة إرسال تنبيهات مستقلة.
- الاستعادة تفحص كل جداول الهدف قبل الكتابة، بدل المستخدمين فقط. الكتابة والمسح الاختياري والتحقق داخل transaction واحدة؛ الخطأ يعيد الحالة السابقة. قاعدة مهيأة بترحيلات زرعت مشاريع تُرفض قبل أي إدخال، أو تُستعاد باستخدام `--wipe` على هدف تعافٍ منفصل مقصود.
- تحديثات متوافقة لـmorgan وproxy-addr وbrace-expansion. بقي تحذير uuid المتوسط عبر exceljs المقبول سابقًا؛ لم نغيّر multer إلى الإصدار 2 أو نجري تحديثات كاسرة.

## ترتيب التفعيل

قبل التفعيل: شغّل `npm run storage:audit` على مضيف التطبيق وتحقق من الملفات المفقودة والسعة؛ النسخ الكامل يرفض إعلان النجاح إذا كانت ملفات مرجعية مفقودة. احتفظ بنسخة قاعدة بيانات حالية مستقلة أثناء معالجة أي نقص.

1. نشر سكربت الموقع النشط من Apps Script (الموقع الثاني غير مستخدم حاليًا ويُحدّث قبل تشغيله). الملفات من ريبو الواجهة (`google-sheet/Code.gs` و`Code-site2.gs`) على Web Apps المستخدمة أولًا. الاحتفاظ بإعدادات الأسرار والمجلدات الحالية. نشر Cloudflare وحده **لا ينشر Apps Script**.
2. نشر الباك إند بالتبعيات المحدّثة. لا توجد migration جديدة.
3. تشغيل نسخة يدوية من لوحة الإدارة، والتحقق أنها إصدار 2 وتحتوي `fileManifest` وأن كائناتها موجودة على Drive. لا يكفي رد `/health` لإثبات نجاح النسخ.
4. تنزيل نسخة فعلية وكائناتها وتجربة التعافي على خدمة وقاعدة وUPLOAD_DIR منفصلين.

نشر الباك إند قبل تحديث Apps Script يجعل إجراء `backup-file` غير معروف ويُفشل النسخ الكامل. النسخ القديمة تبقى؛ لا تعدّل ترتيب التفعيل.

## نسخة كاملة مستقلة

على مضيف التطبيق، باستخدام إعداداته الحالية (DATABASE_URL وUPLOAD_DIR):

```sh
npm run backup:complete -- /path/to/new-backup-directory
```

المجلد الناتج يحتوي `database.json` و`files/`. يتطلب مسارًا جديدًا ويرفض استبدال نسخة موجودة. انسخ **المجلد كله** إلى تخزين مستقل؛ وجوده على نفس Volume لا يحمي من فقد الـVolume. إذا فشل الأمر، لا تعتبر المجلد الجزئي نسخة مكتملة. الأمر القديم `backup:local` ما زال نسخة قاعدة بيانات فقط.

## الاستعادة

على هدف تعافٍ منفصل، اضبط DATABASE_URL وUPLOAD_DIR إلى الهدف. استخرج ملفات Drive إلى مجلد محلي؛ تحقق من الأسماء `<sha256>.json` بعد التنزيل. UPLOAD_DIR يجب أن يكون فارغًا:

```sh
npx ts-node --transpile-only scripts/restore-backup.ts /path/database.json --files-dir=/path/files
```

لو الهدف يحتوي بيانات ابتدائية من migrations، أضف `--wipe` **فقط للهدف المنفصل الذي تقصد استبداله**. هذا الخيار يمسح بيانات الهدف داخل transaction. لا تشغله عشوائيًا على قاعدة الإنتاج.

النسخة التي تحتوي `missingFiles` تُرفض للاستعادة الكاملة. استعادة البيانات والملفات المتاحة فقط تتطلب الخيار الصريح `--allow-missing-files`، مع بقاء مراجع الملفات المفقودة في قاعدة البيانات وتحذير واضح. لا يُنشئ السكربت محتوى بديلًا لتلك الملفات.

قبل الكتابة يتحقق السكربت من اكتمال manifest وبصمات كل الملفات. يرفض الكتابة فوق ملفات موجودة. عند خطأ عادي يرجع transaction ويحذف الملفات التي أنشأها أثناء المحاولة. انقطاع العملية/المضيف فجأة ليس transaction موزعة بين MySQL والقرص؛ بعده راجع الهدف وأعد التعافي إلى دليل فارغ. النسخ القديمة إصدار 1 تظل مدعومة مع تحذير أنها لا تستعيد محتوى الملفات.

## حصر التخزين بدون حذف

```sh
npm run storage:audit
```

يفحص الملفات المرجعية والمفقودة واليتيمة وأحجامها ومساحة filesystem. لا يحذف شيئًا. أرقام ذاكرة هذا الأمر تخص عملية الفحص، وليست استهلاك عملية الويب. شغّله على مضيف التطبيق للحصول على مساحة الـVolume الصحيحة. لا تستخدم نتائج بيئة التطوير لتوقع عمر سعة الإنتاج.

## التحقق والحدود

التحقق تم محليًا ببيانات مصطنعة: اختبارات التطبيق والانحدار، اختبارات Apps Script بمحاكاة Drive، نسخة كاملة واستعادة مع تطابق الملف، وفشل متعمد بعد `--wipe` أكد رجوع البيانات السابقة. نجح البناء، و267 اختبارًا في 22 ملفًا، و6 اختبارات لسكربتي Google. فحص التبعيات: صفر حرج وصفر عالٍ، وحزمتان بتصنيف متوسط بسبب uuid.

لم تُختبر Google Apps Script أو نسخة فعلية على Drive/Railway في الإنتاج، ولم تُنشر تغييرات النسخ الكامل؛ إصدار الأمان المستقل نُشر كما هو موضح أعلاه. يلزم وصول إدارة الخدمات لإتمام ذلك والتحقق من المسار الدائم والصلاحيات والسعة.

ما زال قياس الإنتاج ضروريًا: snapshot قاعدة البيانات وJSON/Base64 يستهلكان ذاكرة تتناسب مع حجمها، ونقل كل الملفات أول مرة يستغرق وقتًا وحصة Google. الحد الجديد لفك ضغط Excel يقلل خطر ZIP bombs لكنه لا يجعل مهلة الختم تلغي المعالجة الجارية. يلزم قياس RAM وقت النسخ والختم، وحدود الفاتورة، وتوصيل تنبيه خارجي لحالة النسخة المتقادمة والمساحة. لا يوجد حذف تلقائي لملفات الأعمال أو تغيير لنافذة متابعة Google البالغة 45 يومًا؛ هذه سياسات احتفاظ/عمل لا تُغيّر دون حاجة مثبتة.

من أجل تطابق دقيق بين الملفات المتغيرة ولقطة قاعدة البيانات أثناء تعافٍ حساس، خذ النسخة في نافذة توقف كتابة أو استخدم snapshots منسقة للقاعدة والتخزين. transaction قاعدة البيانات وحدها لا تقفل نظام الملفات.

## تحديث نوفمبر 2026 (قرار صاحب المشروع)
- الملفات المفقودة من التخزين **مابقتش بتفشّل النسخة**: بتتسجل في `missingFiles` وتظهر كملاحظة في حالة النسخة، والنسخة تتسجل نجاح.
- ملفات حسابات `BACKUP_SKIP_FILE_OWNERS` (إيميلات مفصولة بفاصلة؛ الافتراضي حساب صاحب المشروع) مش بتتنسخ — صفوفها في الجداول بتفضل، ومساراتها في `skippedFiles`.
- `restore-backup.ts` بيكمل الاستعادة مع `missingFiles` و`skippedFiles` بتحذير، من غير `--allow-missing-files` (الخيار ده اتلغى).
